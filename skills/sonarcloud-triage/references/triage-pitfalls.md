# Context-sensitive findings

These examples derive from a 55-issue review of `worxbend_obs-websocket-client` at revision `b994a9c0f8d0cdb15f28618dfb18e4d7da235f76`. Counts and project policy are historical examples, not global requirements.

- **GitHub Actions S7630:** direct expression interpolation in a shell is fragile even if an earlier required job validates that exact input. Verify `needs`, conditions, and failure behavior before describing exploitability. Prefer environment data and quoted shell arguments at the sink as well.
- **S2068 test credentials:** inspect whether values authenticate to anything real. Synthetic passwords, invalid credential-bearing URIs, `password=<set>`, `<unset>`, and HOCON null values can intentionally test rejection/redaction. Do not delete those cases or randomize them merely to silence the scanner. Recommend a narrow false-positive disposition with evidence; do not apply it remotely without authorization.
- **S8707 CLI paths:** an arbitrary output path can be an intentional command-line contract. Establish the caller and authorized destination before imposing confinement. A build-only writer whose contract is Mill-managed output can validate under `out/`; a general export command may correctly allow an explicit external path. Directory creation and file writes from one tainted argument are distinct reported sinks, often one root cause. `resolve()` plus ancestry checks handle existing symlinks, but are not a race-proof sandbox against concurrent hostile filesystem mutation.
- **S5443 temporary paths:** inspect the actual filesystem namespace. A fixed `/tmp` directory in a unique disposable container with no host mounts is different from a shared host path. Prefer private owned state for configuration and logs; retain required third-party rendezvous paths such as X11 sockets when the isolation justifies them. Changing a literal into a constant is not a security fix.
- **S3776 frozen benchmark:** refactoring a verbatim legacy implementation can destroy the experimental baseline. Keep it intact and document the intentional exception; improve production code separately. Never exclude an entire production module merely to lower issue counts.
- **S6353 regex simplification:** Python `\w` matches Unicode by default. Replacing ASCII ranges mechanically can expand the language accepted by a validator or code generator. Preserve flags/semantics and test non-ASCII inputs. Global `re.ASCII` can also narrow existing `\s` matches; use a scoped identifier group when whitespace must remain Unicode-aware.
- **S8786 regex performance:** an unanchored digit run followed by a suffix can retry at every position in a long near miss. Check adversarial nonmatching input, not only successful matches. Local tool input lowers exposure but does not remove unnecessary work.

Official references: [GitHub script injection](https://docs.github.com/en/actions/concepts/security/script-injections), [Python regular expressions](https://docs.python.org/3/library/re.html), [Python temporary files](https://docs.python.org/3/library/tempfile.html). Verify the actual server's API and rule metadata rather than assuming rule keys or severity schemes are identical across versions.
